title: Configuration

All services are configured with environment variables. None of them reads a config file. Defaults match the local setup from [Run locally](/docs/self-hosting/local).

## Shared

`DATABASE_URL` is read by every service and by the migration and seed scripts, through `connect()` in [`packages/db/src/index.ts`](https://github.com/eviatarmor/Readmeter/blob/main/packages/db/src/index.ts). The default is the Compose database:

```sh
DATABASE_URL=postgres://readmeter:readmeter@127.0.0.1:5442/readmeter
```

Each process opens a postgres.js pool of at most 10 connections. connector-gcp opens a second pool of at most 4 connections for its advisory locks.

These limits are set in code and have no variable:

| Limit | Value | When exceeded |
|---|---|---|
| Request body | 1 MiB | `413 batch_too_large` |
| Events per batch | 10,000 | `413 batch_too_large` |
| Findings per batch | 1,000 | `413 batch_too_large` |
| Store writes in flight | 64 | `503 busy` with `Retry-After: 5` |
| Rate limit buckets per process | 10,000 projects and 10,000 client IPs | The least recently used bucket is dropped and starts full again |
| API key cache | 30 seconds | Revocations, origin edits and project rate limits take effect within this time |
| Projects with rule state in memory | 1,024 | The least recently active project's window state is dropped |

Rate limits are held in each ingest process. With several ingest instances behind a load balancer, each one enforces them separately. See [Security](/docs/self-hosting/security#rate-limits-and-backpressure).

A connection is synced when it has never synced, when its last sync is more than six hours old, or when a sync was requested from the console. These intervals are not configurable.

## Database package and scripts

| Variable | Read by | Effect |
|---|---|---|
| `READMETER_EVENTS_RETENTION_DAYS`, `READMETER_FINDINGS_RETENTION_DAYS`, `READMETER_ROLLUP_RETENTION_DAYS` | `pnpm db:retention`, `readmeter retention` | Same meaning as for the worker; one pass, then exit. |
| `DATABASE_URL` | `pnpm db:migrate`, `pnpm db:retention`, `pnpm db:seed`, `pnpm db:generate` (drizzle-kit), `scripts/dev-common.sh`, `scripts/read-hash-key.mjs` | Database to use. `dev-common.sh` exports the local default when unset. |
| `READMETER_PG_PORT` | `docker-compose.yml` | Host port for the Postgres container. Default `5442`. |
| `READMETER_DEV_KEY` | `packages/db/src/seed.ts` | API key seeded for `proj_demo`. Default `rm_dev_key`. |
| `NODE_ENV` | `seed.ts`, `seed-user.ts` | `production` skips both seeds. |
| `OUT` | `scripts/build-wasm-server.sh` | Output directory for the server core. Default `apps/ingest/wasm`. ingest and console-api load the core from that directory, so leave it unset unless you copy the files there yourself. |
| `READMETER_SECRET_KEY` | `scripts/dev-up.sh`, `scripts/e2e.sh` | Set to a fixed development key when unset, for the local console-api and connector. |
| `READMETER_GCP_FAKE`, `READMETER_GCP_POLL_MS` | `scripts/e2e.sh` | Set to `1` and `500` so the end-to-end test syncs fake Google Cloud data quickly. |

The Compose database uses user `readmeter`, password `readmeter` and database `readmeter`. These are fixed in `docker-compose.yml` and are meant for local use only.

## Example

A console-api for a console served at `https://readmeter.example.com`, with ingest at `https://ingest.example.com`:

```sh
NODE_ENV=production
DATABASE_URL=postgres://readmeter:...@db.internal:5432/readmeter
PORT=8091
BETTER_AUTH_SECRET=...
BETTER_AUTH_URL=https://readmeter.example.com
CONSOLE_ORIGIN=https://readmeter.example.com
CONSOLE_STATIC_DIR=/srv/readmeter/apps/console-web/dist
INGEST_PUBLIC_URL=https://ingest.example.com
READMETER_SECRET_KEY=...
SMTP_URL=smtps://user:pass@smtp.example.com
MAIL_FROM=readmeter@example.com
```

[Production](/docs/self-hosting/production) explains each of these choices.
